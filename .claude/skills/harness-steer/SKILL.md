# 하네스 스티어링

**실패를 영구적인 방지 장치로 바꾼다.** 이 스킬은 코드를 고치지 않는다.
같은 실패가 다시 일어나지 않게 만드는 것이 산출물이다.

> Hashimoto: *"Anytime you find an agent makes a mistake, you take the time to
> engineer a solution such that the agent never makes that mistake again."*

## 6단계 (건너뛰지 않는다)

1. **재현** — 같은 입력으로 실패를 다시 만든다. 이걸 건너뛰면 유령을 고친다.
2. **분류** — 증상이 아니라 **실패의 종류**를 찾는다.
   가이드 누락 / 센서 부재 / 권한 공백 / 상태 손실 / 관찰 불가 중 무엇인가.
3. **계층 선택** — **가능한 한 아래쪽**을 고른다.

   | 계층 | 신뢰도 | 비용 | 유효 범위 |
   | --- | --- | --- | --- |
   | 프롬프트 | 낮음 | 0 | 그 대화만 |
   | 가이드 규칙 (`AGENTS.md`) | 중간 | 분 | 모든 실행 |
   | 센서 (린트·테스트·스크립트) | 높음 | 시간 | 자동 검출 |
   | 환경 (권한·훅·CI) | 최고 | 시간~일 | 구조적으로 불가능 |

   대화에서 고치고 넘어가는 것은 **고친 게 아니다.**

4. **구현** — 그 계층에 넣는다.
   - 가이드면 `AGENTS.md` §B에 `- (YYYY-MM-DD) 증상 → 원인 → 고친 계층` 형식으로
   - 센서면 `tool/`에 스크립트 + `Makefile` 타깃 + `SENSORS` 등록 + §2 선언
   - 환경이면 `.claude/settings.json` 또는 `hooks/`
5. **검증** — **위반을 일부러 주입해 실제로 막히는지 본다.**
   실패하는 걸 본 적 없는 센서는 센서가 아니다.
6. **등록** — `docs/HARNESS.md` 인벤토리에 추가한다.
   **"막으려는 실패" 칸을 반드시 채운다** — 비면 나중에 이걸 떼도 되는지 판단할 수 없다.

## 언제 승격시키나

| 신호 | 조치 |
| --- | --- |
| 같은 실수 2회 | 가이드 규칙 추가 |
| 같은 실수 3회 | **센서로 전환하고 가이드에서는 지운다** |
| 되돌릴 수 없는 실수 1회 | 즉시 환경(권한·훅)으로 |
| 가이드 규칙이 센서로 대체됨 | 가이드에서 **지운다** (중복은 모순의 씨앗) |

## 반대 방향 — 뗄 것 찾기

스티어링은 더하기만이 아니다. `docs/HARNESS.md`의 **만료 후보** 표를 보고,
"모델이 이걸 혼자 못한다"는 가정이 아직 유효한지 확인한다. 만료된 규칙은 뗀다.

> Anthropic: *"Every component in a harness encodes an assumption about what the
> model can't do on its own, and those assumptions are worth stress testing."*

500개 규칙짜리 하네스는 프로덕션 시스템이 아니라 **안전으로 위장한 병목**이다.

## 출력

```
## 실패
<무엇이 몇 번 일어났나 + 재현 방법>

## 분류
<실패의 종류 — 증상 아님>

## 고칠 계층
<계층 + 왜 그 계층인가. 더 아래를 고를 수 없다면 그 이유>

## 변경
<정확한 파일과 내용>

## 검증
<어떤 위반을 주입해 어떻게 막히는 걸 확인했는가>

## 인벤토리 등록
<docs/HARNESS.md에 추가할 행>
```
