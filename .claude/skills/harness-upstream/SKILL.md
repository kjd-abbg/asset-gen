# 상류 반영

**하네스는 실제 작업 중에 좋아진다.** 여기서 센서를 하나 고치고 저기서 훅을 하나
더하는데, 그것이 키트로 돌아가지 않으면 **다음 프로젝트는 같은 실패를 처음부터
다시 겪는다.** 래칫이 프로젝트 하나 안에서만 돌고 조직 전체로는 돌지 않는 상태다.

이 스킬은 그 역방향을 담당한다. `harness-steer`가 "실패 → 이 프로젝트의 하네스"라면,
이 스킬은 "이 프로젝트의 하네스 → 모든 프로젝트"다.

## 0. 먼저 차이를 본다

```
make harness-upstream
```

무엇이 상류와 다른지, 이 프로젝트에만 있는 센서·훅이 무엇인지 보여준다.
아무것도 안 바꾼다.

## 1. 올릴 것인지 판단한다

**기본값은 "올리지 않는다"이다.** 키트에 들어간 것은 모든 미래 프로젝트가
짊어진다. 틀린 규칙 하나가 N개 저장소에 복제된다.

| 키트로 올린다 | 이 프로젝트에 남긴다 |
| --- | --- |
| 모든 스택에서 참인 규칙 | 특정 도구·버전에 묶인 것 |
| 실패의 **종류**를 막는 구조 | 특정 실패의 **증상** |
| 기계로 검사 가능한 것 | 주관적 판단이 필요한 것 |
| 비어 있어도 해롭지 않은 뼈대 | 채워두면 낡는 내용 |

**세 가지 질문으로 거른다.**

1. **다른 스택에서도 참인가?** — "npm에서는" "Next 16에서는"이 붙으면 아니다.
   그 경우 키트의 `docs/EVIDENCE.md`에 **사례로** 넣는 것이 맞는 자리다.
2. **비어 있어도 해롭지 않은가?** — 키트는 스택을 모르는 채로 배치된다.
   채워야만 의미가 있는 내용은 뼈대만 올리고 내용은 남긴다.
3. **이미 다른 프로젝트에서도 겪었는가?** — 한 번 겪은 것은 우연일 수 있다.
   두 번째 프로젝트에서 또 나오면 그때 올린다. **성급한 일반화가 낡은 규칙의
   가장 흔한 출처다.**

## 2. 애매하면 사례로 넣는다

규칙으로 올릴지 애매하면 `docs/EVIDENCE.md`에 실패 사례로 넣는다.
**사례는 낡아도 참고로 남지만, 코어에 박힌 거짓은 에이전트가 그대로 믿는다.**

사례 형식: 무슨 일이 있었나 / 왜 그랬나 / 어떻게 고쳤나 / 날짜.

## 3. 올린다 — 파일만 복사하지 않는다

키트를 고칠 때는 **넷이 함께 움직인다.** 하나라도 빠지면 다음 사람이 그 규칙이
왜 있는지 모른 채 지운다.

1. **구현** — `template/` 아래 해당 파일
2. **셀프테스트** — `tool/selftest.sh`에 위반 주입 케이스를 더한다.
   **실패하는 걸 본 적 없는 센서는 센서가 아니다.**
3. **인벤토리** — `template/docs/HARNESS.md.template`에 "막으려는 실패"와 함께
4. **근거** — `docs/SOURCES.md`에 왜 이 규칙이 정당한지.
   1차 출처가 없으면 **"실측 근거만 있다"고 솔직히 적는다.**

그리고 `sh tool/selftest.sh`가 통과해야 한다. 이건 협상 대상이 아니다 —
키트가 깨지면 그 뒤 모든 프로젝트가 깨진 채로 시작한다.

## 4. PR

```
git -C <키트> checkout -b fix/<무엇>
# 위 1~4를 고친다
sh <키트>/tool/selftest.sh          # 반드시 통과
gh pr create --repo ABBG-DevTeam/agent-harness-kit
```

PR 본문에 **어느 프로젝트의 어떤 실패에서 나왔는지** 적는다. 그것이 나중에
"이 규칙 아직 필요한가"를 판단하는 유일한 근거가 된다.

## 5. 머지 후

각 프로젝트에서:

```
sh <키트>/init.sh . --update
make harness-check && make check
```

`--update`는 인프라만 갱신하고 `AGENTS.md`·`Makefile`·상태 파일은 건드리지
않는다. 갱신 후 센서가 깨지면 그것 자체가 정보다 — 가이드와 인프라가 어긋난 것이다.

## 반대 방향도 본다

올리는 것만이 아니다. 키트의 규칙 중 **이 프로젝트에서 계속 방해가 되는 것**이
있으면 그것도 신호다. 키트의 `docs/HARNESS.md` "만료 후보"에 올리거나, 왜 이
프로젝트만 예외인지 `decisions.md`에 남긴다. 조용히 끄는 것이 가장 나쁘다.
