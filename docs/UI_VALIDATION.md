# UI 전환·캐시·브라우저 검증

UI가 있는 프로젝트의 작업·회귀 검증 기준. UI가 없으면 적용 대상에서 제외.
키트 관리 문서로 신규 배치와 `--update`에 포함되며, 프로젝트별 예외·측정값은
해당 프로젝트의 상태 파일과 테스트에 기록. 이 문서 자체는 자동 UI 센서가 아님.

## 브라우저 실행

- 기본은 **headless**. 직접 확인 요청도 창을 띄우라는 뜻으로 확대 해석하지 말 것.
- 사용자가 명시적으로 화면 공유·가시 브라우저 실행을 요청한 경우에만 headed 실행.
  사용자 탭·프로필을 재사용하거나 포커스를 가져오지 말고 별도 테스트 컨텍스트 사용.
- 스크린샷·영상·DOM·프레임 기록은 headless에서도 수집 가능.
- 성공·실패 모두 테스트 컨텍스트를 `finally`에서 닫기. 남은 프로세스 정리는
  에이전트가 생성한 PID·임시 프로필만 대상으로 한정. 브라우저 전체 종료 금지.
- 공유 작업 공간에서는 개발 서버·빌드가 같은 산출물 디렉터리를 동시에 쓰는지 확인.
  개발/운영 미리보기 전환 후 주소·모드·소스 수정 반영 방법을 인계.

- 라우트·레이아웃 슬롯 추가 같은 구조 변경 뒤에는 HMR 상태를 검증으로 인정하지 말고 개발 서버 재시작과 새 브라우저 컨텍스트에서 확인(사례 D6).
- 사용자 콘텐츠를 `srcdoc` iframe으로 미리볼 때 `#앵커`·상대 링크가 부모 주소로 해석돼 앱이 iframe 안에 중첩될 수 있음. 링크를 가로채 처리하고 미리보기에서 눌러 볼 것.

## 먼저 기록할 것

프레임워크·라우터 버전, 개발/운영 모드, 브라우저·화면 너비, 인증 상태,
실제/대체 데이터, 캐시 준비 상태, 네트워크 지연 조건을 기록.
설치된 버전의 코드·공식 문서로 해당 동작을 확인한 뒤 구현 방법 선택.
특정 프로젝트에서 사용한 캐시 시간·prefetch 설정·애니메이션 시간을 공통 기본값으로 복사하지 말 것.

## 전환 계약

| 구간 | 확인할 동작 | 실패 예 |
| --- | --- | --- |
| 클릭 → 첫 피드백 | 첫 방문·캐시 재방문을 각각 측정. 네트워크 전 표시가 필요한 틀은 클라이언트에서 준비 | 서버 응답 전에는 loading UI도 안 뜸 |
| 스켈레톤 → 본문 | 후속 화면이 실제 마운트될 때 넘기고, 창·배경·스크롤 잠금의 연속성 유지 | 라우팅 pending 종료 때 먼저 닫아 창이 재등장 |
| 닫기·취소 | 로딩 중 닫기, Escape, 뒤로가기, 다른 목적지로 이동 검사 | 늦은 응답이 취소한 창을 다시 엶 |
| 모달 내부 이동 | 목록→상세→작성과 닫기 후 복귀 위치를 명시 | 중복 history, 배경 스크롤 이동 |
| 입력·문서 편집 | 데이터 갱신·탭 전환 중 값·포커스·선택 영역 보존 | 재마운트·진입 효과가 입력을 초기화 |
| 모션 | UI 역할에 맞는 범위·속도, 최초 진입과 갱신 구분 | 검색창·테이블까지 서로 다른 시차로 들썩임 |

타이머는 첫 피드백의 지연 허용 범위를 조절할 때 사용. 후속 UI 준비 신호를 임의의
타이머나 라우팅 pending 종료로 대체하지 말 것. 취소·오류·리다이렉트도 정리 경로 필요.

## 최소 회귀 행렬

- 캐시 없는 첫 진입 / 캐시 준비 후 재열기 / 캐시 만료·무효화 후 재열기.
- 빠른 응답 / 의도적으로 늦춘 응답·화면 코드 로드 / 실패 응답.
- 로딩 중 닫기 / 닫은 뒤 늦은 응답 / 연속 클릭·다른 목적지 이동 / 뒤로·앞으로가기.
- 모바일·데스크톱 / 키보드·포커스 / reduced motion.
- 데이터 저장·문의 생성/삭제 등 관련 변경 / 로그아웃·계정 전환 / 권한 변경.

본문 도착 **이후만** 측정하면 교체 직전의 공백을 놓침. 첫 피드백부터 본문 안정화까지
프레임별 표시 상태·창 개수·투명도·경계 상자·스크롤 위치를 수집.
전환 계약에 따라 창 0개인 공백, 의도하지 않은 중첩, 불필요한 재진입·높이 변화를 검사.
스켈레톤과 본문은 같은 폭·반응형 분할·제목/탭/닫기 영역을 기준으로 비교.
스켈레톤은 실제 화면과 같은 구조 컴포넌트·CSS를 공유하고, 주요 영역 경계 상자 차이를 여러 폭에서 비교(사례 D7). 비교 전에 다른 검사가 남긴 스크롤을 초기화. 존재 여부나 재방문 일부 좌표 통과를 동등성으로 보지 말 것.
새로고침·주소 직접 입력처럼 데이터 없이 진입할 때 맞는 스켈레톤을 고르는지도 검사(사례 D8).
복귀 계약: 일반 링크 이동은 맨 위에서 시작, 뒤로가기·닫기는 스크롤과 누른 버튼의 포커스를 되돌림. 복원은 고정 프레임 수가 아니라 준비 신호 뒤에 하고 사용자가 스크롤·키 입력을 하면 중단. 주소 변화 없이 화면만 바꾸는 단계(미리보기, 하위 단계)는 history에 한 칸을 쌓아 뒤로가기가 앱을 떠나지 않게.
지연 주입 예(기본값 아님): 화면 코드 1.1초·데이터 0.7초 지연, CPU 6배 감속, 매 프레임 기록. 예전 버그를 다시 주입해 검사가 실제로 실패하는지 확인.

모션 평가는 정지 스크린샷이나 animation-name 존재 검사로 끝내지 말 것.
프레임 연속 기록·영상으로 순서·가독성·조화를 판단하고, 입력/포커스·리렌더 뒤 재실행도 확인.
수치 검증과 시각적 판단 결과를 각각 기록.

## 캐시 계약

스켈레톤을 숨긴 것과 캐시를 재사용한 것은 별개. 재방문 요청 수와 실제 데이터 표시를 함께 측정.
UI 방문 여부만으로 캐시 적중 판정 금지. 캐시 적중은 본문을 바로 표시하고,
만료·무효화·실패는 필요한 로딩/오류 피드백을 유지.

캐시 대상·키·계정 범위·유효 기간·갱신/무효화 계기를 명시. 저장·삭제·인증 쿠키 변경·로그아웃·
계정/권한 전환 후 이전 내용 재사용 여부를 확인. 개인정보를 전역 공용 캐시나 영구 저장소에
복사하는 방식은 별도 설계 없이 도입하지 말 것. 캐시로 서버 권한 검사를 우회하지 말 것.
캐시 데이터와 저장하지 않은 입력값도 구분하고, 백그라운드 갱신으로 입력을 덮지 않도록 검사.

개발 서버에서 미리 불러오기·캐시가 제한되는 프레임워크는 운영 빌드로 별도 검증.
운영 미리보기는 배포가 아니며, 개발 모드 결과를 배포 성능으로 보고하지 말 것.

## 결과 인계

측정 구간·조건, 첫 피드백/본문 표시 시간, 재방문 요청 수, 캐시 무효화 결과,
전환 중 공백/중첩 여부, 실행한 테스트와 미실행 범위를 남기기.
대체 인증·DB로 검증했다면 실제 로그인·데이터 변경을 검증했다고 보고하지 말 것.
반복 버그는 프로젝트 테스트에 재현 시나리오를 추가. 키트의 배치 selftest 통과를
제품 모달·캐시 동작의 통과로 해석하지 말 것.

사용자 화면의 문구를 만들거나 수정할 때는 [제품 문구 기준](UI_COPY.md)을 함께 읽습니다. 문구 검사와 문맥 검토를 구분하고 실제 화면의 줄바꿈·오류·로딩 안내까지 확인합니다.

## 설명 문단의 폭 확인

실제 문구와 CSS로 재현하고 원문 개행 없는 사례도 포함. 데스크톱·모바일에서 문단과 부모의 bounding box, 계산된 max-width, 문서 가로 넘침을 기록하고 캡처 검토.
비교 영역보다 문단만 좁으면 제한의 의도부터 확인. 정상 자동 줄바꿈이나 승인된 읽기 폭은 오류에서 제외.

공통 스타일을 고치면 설명을 공유하는 화면·스켈레톤도 확인. 문자열 검사·소스 검색·키트 selftest만으로 실제 너비나 시각 품질을 판정하지 말 것.
브라우저 자동화에는 역할별 기대 폭을 명시하고, 제한을 다시 주입했을 때 실패하는지 검증.
