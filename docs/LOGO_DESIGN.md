# 로고·아이콘 제작과 검증

신규 프로젝트의 로고(심볼·워드마크·조합형)와 거기서 파생하는 파비콘·앱 아이콘에 적용.
사용자가 브랜드 자료나 기존 로고를 주면 그 자료가 우선이며, 이 문서는 파생·검증 기준으로만 사용.
대체 텍스트·대비 일반은 [접근성 기준](ACCESSIBILITY.md), 화면 배치는 [UX 기준](UX_DESIGN.md), 렌더 실행 방식은 [UI 검증](UI_VALIDATION.md)을 따를 것.
화면 안 UI 아이콘·공유 미리보기 이미지·일러스트·사진은 [시각 에셋](VISUAL_ASSETS.md)이 맡음.

## 작업 순서

1. 입력 확인: 서비스 이름(한글·영문 표기), 업종, 주 사용자, 톤, 출시 국가, 사용자 제공 자료. 빠진 값은 추측하지 말고 질문하거나 가정으로 명시.
1-2. 로고 브리프 작성: 아래 로고 브리프 절. 브리프 없이 바로 그리지 말 것.
2. 방향 2~3개 제시: 안마다 구성(조합형·워드마크 단독 등), 설명성 수준, 원형/각진 성격, 선택 이유를 한두 줄로. 모든 안을 단색 SVG로 먼저 제시.
3. 선택안 정제: 사용자가 고른 안만 다듬고, 고른 사실과 사람이 지시한 수정을 날짜와 함께 기록(법적 확인 절의 창작 기여 기록).
4. 변형·파생 자산 생성: 아래 구성 요소 표, 파생 아이콘 표 순서.
5. 검증: 검증 표의 전 항목을 렌더 이미지로 확인하고 항목별 판단을 기록.
6. 법적 확인 표시: 상표 검색 결과와 남은 위험을 브랜드 문서에 기재. 등록 가능 여부는 판정하지 않음.
7. 사용 규칙 기록: 색값·여백·최소 크기·금지 사용을 프로젝트 브랜드 문서에 남김.

## 형태 원칙

- 로고의 역할은 식별. 업종 설명이나 판매 문구를 다 담으려 하지 말고, 한 색과 아주 작은 크기에서 재현되는 형태를 먼저 확보 (Rand 1991).
- 극단적 단순화를 기본값으로 삼지 말 것. 첫 노출의 재인·호감은 조화(대칭·균형)가 높고, 정교함이 중간이며, 실제 사물을 연상시키는 자연성이 있는 설계에서 높았음 (Henderson & Cote 1998). 정교함의 호감 효과는 ∩자형이라 과한 디테일도 감점 요인.
- 반복 요소는 재인을 돕고, 완전 대칭보다 약간 벗어난 조화가 더 잘 기억됨. 높이:너비 약 0.75~0.8의 흔한 비율과 평행선 다수는 '본 적 있는 느낌'의 오인을 키움 (Henderson & Cote 1998).
- 설명성: 업종을 드러내는 글자·그림 요소는 무명 신규 서비스의 평가를 높였음. 친숙한 브랜드에서는 효과가 약하고, 업종 자체에 부정적 연상이 있으면 역효과 (Luffarelli et al. 2019).
- 원형은 부드러움·배려, 각진 형태는 단단함·내구성 연상으로 이어지며 서비스 문구가 반대 성격을 말하면 효과가 사라짐 (Jiang et al. 2016). 비대칭은 흥분 성격과 연결 (Bajaj & Bond 2018). 판정 규칙으로 쓰지 말고 안 비교의 참고로만.
- 단순·평면 로고의 효과는 포지셔닝에 따라 달라 고급 제품에서는 반대 결과가 나옴 (Bossel et al. 2019). 고급·전문 서비스라면 정교함을 조금 높인 안을 하나 포함.
- 형태 단계 경고: 원·삼각형·사각형 같은 흔한 도형에 한글 1자나 알파벳 1~2자를 넣은 모노그램, 두 자리 이하 숫자, 흔한 도형만으로 된 표장은 상표심사기준상 식별력이 없는 것으로 봄. 이런 안은 서비스 이름 워드마크와 결합하거나 고유한 형태 요소를 더할 것.

## 로고 브리프

다른 디자이너나 생성 모델이 같은 방향을 그릴 수 있게 형태를 말로 고정하는 단계(실무, 사례 D17).

| 슬롯 | 쓰는 법 |
| --- | --- |
| Concept | 전략과 이름이 하나의 형태가 되는 핵심 생각 한 문장 |
| Symbol | 16px에서도 남는 구조 하나 |
| Visual metaphors | 이름을 그대로 그리지 않는 은유 3~5개 |
| Shape language | 각도·곡률·획 굵기·비례·네거티브 스페이스를 구체적으로 |
| Composition | 워드마크 중심인지, 가로·세로 조합의 우선순위 |
| Effects | SVG에서 편집 가능한 처리(offset, outline, inline, cut, ligature). 필요 없으면 flat |
| Avoid | 업종 상징 클리셰(아래 표), 인터뷰에서 피하겠다고 한 인상 |

- 다른 브랜드 이름을 넣어도 브리프가 성립하거나, 심볼이 업종 아이콘 하나로 요약되면 다시 씀. 3D·목업은 평면 원형이 확정된 뒤에만.
- 배치·구성은 업종 관례를 따르되(`spec/DESIGN-BRIEF.md` 3절) 상징은 업종 클리셰를 피함. 둘은 다른 층위.

| 업종 | 근거 없이 쓰면 클리셰인 상징 (실무, 상용 프롬프트 갤러리 정리) |

| 카페·베이커리 | 커피콩·밀 이삭 자동 선택, 가짜 창업 연도 |
| 패션·뷰티 | 왕관, 다이아몬드 |
| 공공·법률·금융 | 방패·기둥·저울·지붕 단독 |

| 공통 | 하트, 전구, 재활용 화살표, 지구본, 말풍선 |

## 색과 서체

- 순서: 검정 단색 → 흰색 반전 → 색. 단색에서 식별되지 않으면 색으로 메우지 말고 형태를 수정.
- 색 의미에는 보편 경향과 국가별 차이가 함께 있음 (Jonauskaite et al. 2020; Madden et al. 2000). 출시 국가와 업종 관례를 확인하고 색 하나에 의미를 단정하지 말 것. 빨강=흥분, 파랑=유능 같은 성격 연상(Labrecque & Milne 2012)은 후보 비교용 참고.
- 색 후보는 업종 자동 연결(AI=파랑, 친환경=초록)로 고르지 말고 서비스의 상품·사용 장면에서 이유를 찾을 것. 보색·유사색 같은 색상환 관계는 조화 점수가 아님(조합 선호·조화·바탕 위 도형색 선호는 서로 다른 판단, Schloss & Palmer 2011). 후보는 로고가 실제로 놓일 바탕(흰 헤더, 어두운 배경, 브랜드색 면) 위에 올려 비교.
- 색값은 HEX와 용도(기본·반전·단색)로 기록. 배경 위 대비는 접근성 절의 단서를 따름.
- 글자는 path로 변환하고 SVG에 폰트를 내장하거나 외부 폰트를 참조하지 말 것. 변환·경로 최적화 뒤 작은 크기 렌더를 원본과 비교(최적화가 닫기 직전 점을 지워 작은 "T"가 "Γ"처럼 깨진 실패, 2026-09-30).
- 워드마크 글꼴이 서비스 이름의 모든 글자(한글 음절 포함)를 실제로 그리는지 렌더로 확인.
- SIL OFL 폰트는 로고 제작에 추가 허가·표기 없이 사용 가능 (OFL-FAQ 1.1). OFL이 아닌 한국어 무료 폰트는 로고·상표 사용 허용 여부를 폰트별 약관에서 확인하고 약관 URL을 기록. 확인하지 못한 폰트는 쓰지 않음.

## 구성 요소와 변형

| 변형 | 용도 | 규칙 |
| --- | --- | --- |
| 기본 조합 | 헤더, 문서 표지 | 심볼+워드마크 가로형. 필요하면 세로형 추가 |
| 심볼 단독 | 아이콘 원본, 좁은 영역 | 워드마크 없이 식별되는지 검증 |
| 워드마크 단독 | 심볼을 쓸 수 없는 텍스트 맥락 | 서비스 이름 공식 표기 그대로 |
| 국문·영문 조합 | 한글·영문 표기를 모두 쓰는 서비스 | 가로·세로 각각, 같은 심볼 비례. 두 표기의 글자 높이·굵기 균형을 렌더로 확인 |
| 단색 검정·흰색 | 인쇄, 테마·monochrome 아이콘 원본 | 그라디언트·투명도 없이 한 색 |
| 반전 | 어두운 배경 | 색만 바꾸고 형태 유지 |
| 소형 | 약 32px 이하, 파비콘 | 세부를 덜어낸 별도 원본. 기본형 단순 축소 금지 (GOV.UK small crown 방식) |

- 여백: 로고 안의 한 요소 크기를 단위로 정의하고 배수를 숫자로 기록 (GOV.UK는 워드마크의 점 크기를 단위로 사용).
- 최소 크기: 공통 수치를 정하지 말고, 검증 렌더에서 형태가 무너지기 직전 크기를 변형별 px로 기록 (GOV.UK 예: 워드마크 너비 50px, 크라운 16px).
- 금지 사용: 비율 왜곡·늘이기, 그림자·글로우 등 효과, 회전·반전, 혼잡하거나 저대비인 배경, 다른 도형 안에 넣기, 원본 파일 없이 다시 그리기 (GOV.UK; NASA 1976).

## SVG 작성 규칙

- 루트 `<svg>`에 `viewBox` 필수. 크기는 `viewBox`로 정의하고 고정 `width`/`height`는 사용처에서 지정. `viewBox` 너비·높이가 음수면 무효, 0이면 렌더되지 않음 (SVG 2 §8.6).
- `<title>`을 루트의 첫 자식으로 두고 서비스 이름을 넣을 것. 첫 자식이 아닌 title을 인식하지 못하는 UA가 있음 (SVG 2 §5.8). `role="img"`와 `aria-labelledby` 조합은 널리 쓰는 패턴이나 이번 조사에서 원문 미확인.
- 금지: `<script>`, 외부 참조(외부 `href`, `@import`, 웹폰트), 래스터 `<image>` 내장, `<text>`, 에디터 메타데이터. Chromium은 SVG 파비콘을 secure static mode로 렌더해 스크립트·외부 리소스가 동작하지 않음.
- 좌표는 정수나 소수 한 자리로 정리하고 반복 형태는 `<use>`로 재사용. 최적화 도구를 돌린 뒤에도 렌더 결과를 다시 비교.

## 생성 모델을 쓸 때

이미지 생성 모델로 심볼 후보를 만들 때의 파이프라인(실무, 사례 D17). 유료 호출은 사용자 승인 후에만.
1. 모델에는 심볼만 그리게 함. 글자는 금지(모델은 철자를 틀림).
2. 흰 바탕 검정 단색, 한 장에 균등 격자로 셀마다 심볼 하나, 사방 15% 안팎 여백. 그라디언트·그림자·질감·미세 해칭·목업 금지(벡터화가 깨짐).
3. 지시문에 기하 UI 아이콘 기본값이나 브랜드와 무관한 소재를 고정해 넣지 않음. 형태만 설명하는 로고 브리프를 그대로 씀.
4. 결정적 트레이싱으로 path만 있는 SVG로 변환(같은 입력이면 같은 출력). 빈 출력(보이는 픽셀 0)은 거절.
5. 색은 변환 뒤 브랜드 색으로 치환. 이름은 라이선스를 확인한 실제 글꼴로 조판한 뒤 path로 변환해 결합.
6. 결과물에는 사람이 고른 후보와 지시한 수정을 기록(법적 확인 절의 창작 기여 기록).

## 사용처 배치

- SVG `viewBox`는 그려진 범위로 자르고 보호 여백은 사용처에서 줌. 여백을 아트보드에 넣으면 헤더·표지에서 로고가 작아짐(헤더 34px에서 이름 글자가 약 10px, 덱 표지에서 상자의 27%만 차지한 실패, 2026-09-29·10-07).
- 여백 자르기는 멱등이어야 함. 두 번 잘라도 같은 결과여야 하고 기준 프레임을 보존(형태를 바꿀 때마다 자르기가 반복돼 로고가 계속 줄어든 실패, 2026-09-22). 편집 화면과 내보내기는 같은 좌표계를 씀.
- 헤더 로고의 최소 크기는 조합 전체 높이가 아니라 로고 안 이름 글자의 렌더 높이로 측정해 하한을 기록. 사용처(가로형·세로형)에 맞는 변형을 고름.
- 대비 교정이 필요하면 로고 안 글자 묶음만 같은 색조에서 명도를 옮기고 심볼은 그대로 둠. 교정과 검수는 최종 로고를 넣은 뒤 실행(자리표시자 상태에서 검수해 대비 2.89:1·글자 9.9px가 통과된 실패, 2026-10-07).

## 접근성

- 링크 없는 로고 이미지의 대체 텍스트는 서비스 이름만 쓰고 "로고"라는 단어는 넣지 않음.
- 홈으로 가는 로고 링크는 목적지를 포함("서비스명 홈").
- 로고 글자는 WCAG 1.4.3 대비 요구와 1.4.5 이미지 텍스트 제한의 예외. 브랜드 규정이 강제하지 않은 저대비 표현을 작성자가 고른 경우는 면제되지 않고, 링크·컨트롤로 쓰는 로고는 대비가 충분한 변형을 권장 (Understanding 1.4.11).
- 신규 프로젝트에서는 저대비 선택이 곧 작성자 선택이므로 기본·반전 변형을 배경 대비 기준에 맞춰 설계할 것.

## 검증

| 항목 | 방법 | 통과 기준 |
| --- | --- | --- |
| 소형 렌더 | 16·32·48px PNG로 렌더 | 형태가 뭉개지지 않고 소형 변형으로 식별 |
| 단색 실루엣 | 모든 채움을 검정 한 색으로 | 색 없이 식별 |
| 라이트·다크 배경 | 흰색·검정·브랜드색 배경에 기본·반전 배치 | 경계가 사라지지 않음 |
| 그레이스케일 | 채도 0 변환 | 색 차이에만 의존한 요소 없음 |
| 마스크 미리보기 | 원·둥근 사각 마스크, Manifest 40% 원, Android 66dp 영역 겹침 | 핵심 요소가 안전영역 안 |
| 파일 검사 | `viewBox`, 첫 자식 `title`, `<text>`·`<script>`·`<image>`·외부 참조 검색 | 위반 0 |
| 유사성 | 같은 업종 유명 로고, KIPRIS 검색 결과와 나란히 비교 | 혼동될 만한 유사 없음, 비교 대상과 판단 기록 |
| 글자 변환 | path 변환·최적화 전후를 16·24px로 렌더해 비교 | 획 누락·모양 변화 없음 |
| 자르기·변환 | 같은 원본을 두 번 자르고, 같은 입력을 두 번 벡터화 | 결과가 바이트 단위로 같음 |
| 배치 실측 | 최종 로고를 넣은 실제 헤더·문서에서 이름 글자 높이와 배경 대비를 측정 | 기록한 하한 이상, 글자 4.5:1 이상(로고 예외를 쓰지 않는 경우) |
| 인쇄 파일 | 인쇄용 PDF의 내용 검사 | 래스터 이미지·라이브 텍스트 0, 페이지 비율 = viewBox 비율, 색 보존 |

- 렌더는 headless로 수행하고 실행 원칙은 [UI 검증](UI_VALIDATION.md)을 따름. 결과 이미지 경로와 항목별 판단을 함께 남길 것.
- 육안 판단 항목(소형 식별, 유사성)을 자동 검사 통과로 보고하지 말 것.
- 합성 예제로 만든 검사가 모두 통과해도 실제로 저장·배포된 결과물을 따로 열어 확인(센서 전부 통과 상태에서 실제 생성물에 결함 10건이 있던 실패, 2026-10-07).

## 법적 확인

- 상표 검색: [KIPRIS](https://www.kipris.or.kr/)에서 서비스 이름(한글·영문·발음 유사)과 도형을 검색. 해외 출시가 있으면 [USPTO Trademark Search](https://tmsearch.uspto.gov/)와 [WIPO Global Brand Database](https://branddb.wipo.int/)도 검색.
- 위험 표시 기준: 상표법 제33조①(식별력 없는 표장, 간단하고 흔한 표장 포함), 제34조①7(선출원 등록상표와 동일·유사하고 지정상품도 동일·유사).
- 한국 특허청은 2025-10-01부터 지식재산처. 심사기준·안내 자료를 찾을 때 두 이름을 모두 사용.
- AI 생성물: 사람의 창작적 기여가 없는 생성물은 미국·한국 모두 저작권 보호가 어렵고, 미국 저작권청은 프롬프트만으로는 통제가 부족하다고 봄 (USCO 2025). 사람이 고른 안, 지시한 수정, 직접 고친 부분을 날짜와 함께 기록.
- 문자·흔한 도형 위주의 단순한 로고는 AI 사용과 무관하게 저작권 보호가 약하며, 상표 보호는 사용·등록으로 별도 성립 (USCO Compendium §914).
- 에이전트 범위는 검색 수행과 위험 표시까지. 등록 가능성·침해 판정은 변리사·법무 검토로 넘기고 보고에 "법적 판정 아님"을 명시.

## 산출물

경로는 스택 관례에 맞춰 정하고 특정 프레임워크 경로를 공통값으로 쓰지 말 것.
- 원본 SVG: 기본 조합, 심볼, 워드마크, 단색 검정·흰색, 반전, 소형.
- 아이콘 세트: SVG 파비콘과 PNG/ICO 폴백, Manifest용 `any`·`maskable`·`monochrome`, 플랫폼 앱 아이콘 원본.
- 인쇄·간판용: 벡터 PDF(래스터·라이브 텍스트 없이, 글자 아웃라인). 이미지·마스크·그라디언트처럼 벡터로 옮길 수 없는 요소가 있으면 조용히 래스터로 굽지 말고 그 사실을 알림. RGB·CMYK 중 무엇인지 명시(CMYK 단순 변환값은 인쇄소 확인 필요로 표시). 인쇄소·간판 업체는 벡터 PDF·AI·EPS를 요구하는 경우가 많음.
- 디지털용 투명 PNG를 쓰는 너비별로(모서리 완전 투명, 로고 픽셀 존재 확인).
- 브랜드 문서 1개: 색값(HEX·RGB, 인쇄가 있으면 CMYK), 여백 단위, 변형별 최소 크기, 금지 사용, 사용 폰트와 라이선스 URL, 검증 이미지와 판단, 상표 검색 일자·검색어·결과, 사람의 선택·수정 기록. 문서가 안내하는 파일 형식과 실제 제공 파일이 같아야 함.
